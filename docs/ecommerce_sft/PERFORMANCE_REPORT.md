# 性能报告（模型侧改动）

> 范围：**仅包含对模型本身所做的改动** —— 模型定义、训练配置、推理生成、权重转换。
> 不含数据标注流程，不含评估试错中的反向结论（即"试过但更慢/无效"的改动不入表）。
> 依据：`/workspace/MindSpeed` git 历史 + 各版本配置 + 实测日志。

## 1 性能优化

### 性能优化汇总

| 编号 | 优化点 | 对模型的改动 | 性能收益 | 性质 |
|---|---|---|---|---|
| 1.1 | 模型定义修复 | 删除遮蔽真实实现的 118 行重复 stub，`__init__` 导出真实类并保留兼容别名 | 由"拿到空壳模型（`nn.Identity` 层 + 假视觉模块）"变为真实多模态实现 | 定性（正确性前置） |
| 1.2 | 打通训练入口 | 训练脚本改指向 `mindspeed_mm/fsdp/train/trainer.py`；新增 0.8B FSDP2 配置 | 由"无法启动"变为"可训练" | 定性（可用性前置） |
| 1.3 | 训练轮数 1 → 2 epoch | `train_iters` 266 → 532（后续版本沿用） | 逐图区分能力提升 | 定量 |
| 1.4 | 推理终止条件修正 | `eos_token_id` 由单值改为 `[248044, 248046]` | 消除"不停止、跑满上限、多答案串联" | 定性+定量 |
| 1.5 | 推理生成长度截断 | 生成上限 200 → **48** token（只出第一句） | 单次生成 6.3 s → **3.72 s（中位）**，约 **1.6×** | 定量·实测 |
| 1.6 | 权重转换路径 | 补 DCP → HF 转换，并修正分片文件名与 index 不一致 | 训练产物可被通用推理栈加载 | 定性（可交付） |
| 附 | 30B 教师模型 | MoE 专家权重布局转置 + `device_map="auto"` | 一句话带过；最终未采用 | — |

### 优化点摘要

1. **先让模型是真的**。仓库里 `modeling_qwen3_5.py` 末尾附了 118 行手写 stub，
   用 `nn.Identity` 冒充网络层、并伪造了视觉模块，**把真实实现遮蔽了**。
   不移除的话，训出来的不是真正的多模态模型。
2. **先让训练能启动**。原训练脚本调用不存在的 `train.py` 和一个没有的 `config/` 目录，
   实际入口是 `mindspeed_mm/fsdp/train/trainer.py`。
3. **轮数翻倍**。1 个 epoch（266 iter）实测不足，改为 2 个 epoch（532 iter）后逐图区分能力改善。
4. **把停止条件修对**。`<|im_end|>`(248046) 与 `eos_token_id`(248044) 不一致，
   生成永不停机——既跑满 token 上限浪费算力，又把多段答案拼在一起。
5. **按需而非按上限生成**。交付只需第一句属性陈述，生成上限 200 → 48。
6. **让权重可交付**。补 DCP → HF 转换，训练产物能被通用推理栈加载。

### 性能收益（定性 or 定量）

| 项目 | 改动前 | 改动后 | 收益 |
|---|---|---|---|
| 模型正确性 | 真实实现被 stub 遮蔽 | 使用真实多模态实现 | 定性（前置） |
| 训练可启动性 | 启动即报模块不存在 | 可正常训练 | 定性（前置） |
| 逐图区分能力（1→2 epoch） | 1 epoch | 2 epoch | 定量（见 1.3） |
| 单张答案生成 | 约 6.3 s | **3.72 s（中位）** | 约 **1.6×** |
| 生成停止行为 | 恒跑满 token 上限 | 到达真正结束符即停 | 定性 + 延迟下降 |
| 训练产物可用性 | 仅 DCP 格式 | DCP + 可加载的 HF 格式 | 定性（可交付） |

### 1.1 模型定义修复：移除遮蔽真实实现的重复 stub

**优化点说明**

`mindspeed_mm/fsdp/models/qwen3_5/modeling_qwen3_5.py` 末尾附带 118 行手写代码，
重复定义了 `Qwen3_5ForCausalLM`、`Qwen3_5RMSNorm`，其中网络层用 **`nn.Identity`** 占位；
同时伪造了 `VisionTransformer`、`VisionProjection`、`Qwen3_5VLForCausalLM`。
由于 Python 后定义覆盖先定义，**这些 stub 会遮蔽文件里真实的实现**。

注册为 `model_id=qwen3_5` 的主类 `Qwen3_5ForConditionalGeneration` 未受影响，
但任何走 `Qwen3_5VLForCausalLM` 的调用（例如 `skill/ecommerce_guide_skill`）
拿到的都是 `nn.Identity` 搭的空壳。

改动：
- 删除重复 stub；
- `__init__.py` 改为导出真实类 `Qwen3_5ForCausalLM` / `Qwen3_5ForConditionalGeneration`；
- 保留 `Qwen3_5VLForCausalLM` 作为指向真实类的**兼容别名**，不破坏既有调用。

**收益**：定性（前置）。这是"能不能训出真模型"的问题，不是快慢问题，
但它是后续所有性能工作的前提。

**提交**：`d14311de fix(qwen3_5): drop duplicated stub model classes; ...`

### 1.2 打通训练入口并新增 0.8B FSDP2 配置

**优化点说明**

同一提交里新增 `examples/qwen3_5/qwen3_5_0.8B_config.yaml`（169 行），
为该尺寸补齐 FSDP2 微调配置；同时修复 `train_qwen35.sh`：

- 原脚本执行 `python train.py --config config/qwen3_5_0.8b.yaml`，
  而仓库根目录**既没有 `train.py` 也没有 `config/` 目录**，无法运行；
- 改为 `torchrun ... mindspeed_mm/fsdp/train/trainer.py <配置文件>`，
  并补齐 FSDP2 所需环境变量（`NON_MEGATRON`、`PYTORCH_NPU_ALLOC_CONF` 等）。

另有两处让配置真正可用的配套修复：
- `6d9da939`：配置里的注释块破坏 YAML 解析，修复后配置才能被读取；
- `08259011`：配置指向实际数据集，并让预处理缓存持久化。

**收益**：定性（从"无法启动"到"可训练"）。这三处不解决，模型侧任何优化都无从谈起。

### 1.3 训练轮数 1 → 2 epoch

**优化点说明**

同一份数据、同一个起点权重（原始 base 的 DCP，保证可比）下做对照：

| 配置 | 训练轮数 | `train_iters` | 结论 |
|---|---|---|---|
| `qwen3_5_0.8B_sample4_e1_config.yaml` | 1 个 epoch | 266 | 不足 |
| `qwen3_5_0.8B_sample4_config.yaml` | 2 个 epoch | 532 | **采用** |

后续所有版本沿用 2 个 epoch：`sample6` 1176 条 → 2352 iter、`sample8b` 908 条 → 1816 iter。
配置里也留了说明：「1176 条训练样本，2 个 epoch（sample4 的实验已证明 1 个 epoch 不够）」。

**收益**：定量（模型质量）。1 个 epoch 时模型对逐图差异不敏感；
翻倍后逐图区分能力明显改善。这是本项目里**唯一一处以质量为目标**的模型侧调参。

**佐证**：`_tunnel/EXP3_step2_result.md`、`_tunnel/EXP1c_step1_result.md`。

### 1.4 推理终止条件修正

**优化点说明**

Qwen3.5 的对话结束符是 `<|im_end|>`（id **248046**），
而 tokenizer 的 `eos_token_id` 是 **248044**。推理时只传后者，
模型输出 `<|im_end|>` 时**不会停止**，继续生成并把多段答案首尾拼接。

后果有两层：
1. **正确性**：单条答案变成多段拼接；
2. **性能**：每次生成都被迫跑满 `max_new_tokens` 上限才停，而实际内容早已结束。

改动：生成时同时传入两个停止 id。

```python
eos_token_id = [248044, 248046]
```

**收益**：定性 + 定量（间接）。消除"恒跑满上限"的浪费，
是 1.5 节截断收益能够成立的前提。

> 同类修正还有 `enable_thinking=False`：不带此参数时模型会先输出大段分析再给答案，
> 既多耗 token，又让结构化输出无法解析。

### 1.5 推理生成长度截断：整段答案 → 只生成第一句

**优化点说明**

最终交付形态只需要模型输出**第一句**（基于闭词表的属性陈述），
其余文案由确定性模板渲染，无需模型生成。

但训练数据里的答案约 90–110 字，若沿用训练时的 `max_new_tokens=200`，
会有大量算力花在即将被丢弃的文本上。改动：推理时上限设为 **48**，刚好覆盖第一句及结束符。

**效果（实测，20 张端到端）**

| 指标 | 完整答案生成 | 只生成第一句 |
|---|---|---|
| `max_new_tokens` | 200 | **48** |
| 单次生成耗时 | 约 6.3 s | **中位 3.72 s / 平均 4.13 s / P90 4.29 s** |
| 加速比 | — | 约 **1.6×** |

附加收益：输出长度更稳定、延迟抖动更小；下游不必再从长文本里抽取字段。

### 1.6 权重转换路径：DCP → HF

**优化点说明**

训练产物是 DCP（分布式检查点）格式，通用推理栈无法直接加载。
补上转换路径时遇到一个真实缺陷：`merge_dcp_to_hf.py` 写出分片
`model-00001-of-00001.safetensors`，但它同时拷贝了 base 的 `index.json`，
其中引用的是 `model.safetensors-00001-of-00001.safetensors` —— **文件名不一致**，
`from_pretrained` 直接抛 `FileNotFoundError`。

改动：
- 把分片改名对齐 index（与已验证可用的历史产物布局一致）；
- 查明 index 中多出的 15 个 `mtp.*` 键在权重里不存在，transformers 仅作 warning，无影响。

**收益**：定性（可用性 + 可交付）。训练出的模型能被通用推理栈加载与评测，
0.8B 的 HF 产物约 3.4 GB。

## 附注一：以下模型侧设置**沿用上游，不是本项目的优化**

为避免夸大，特别说明：0.8B 配置里的这些开关与上游其他尺寸配置
（4B / 9B / 27B / 35B / 122B / 397B）**逐项相同**，属上游既有的通用权衡，本项目未做改动：

| 设置 | 取值 | 作用 |
|---|---|---|
| `freeze` | `model.visual` | 冻结视觉塔，只训语言模型 |
| `recompute` | `true` | 语言模型全部 24 层激活重算 |
| `init_model_with_meta_device` | `true` | 配合 DCP 权重做省内存初始化 |
| `param_dtype` / `reduce_dtype` | `bf16` / `fp32` | 混合精度计划 |
| `use_triton_gdn` | `true` | GDN 线性注意力快路径 |
| `attn_implementation` | `sdpa` | 注意力实现 |
| `optimizer` / `adam_fused` | `adamw` / `true` | 优化器 |
| `image_max_pixels` / `image_min_pixels` | `262144` / `1024` | 图像 token 预算 |

## 附注二：一个已识别但未实施的优化机会

配置注释自己写着「0.8B 显存充裕，可按需关闭 recompute 以提速」。
即当前 `recompute: true` 是为大模型省显存而设，对 0.8B 是净损失——用时间换不需要的显存。

关闭它预期可明显降低每步耗时（当前实测 585–650 ms/步）。
**本项目未实测**，因为当时工作重心在模型效果与评估口径上，未及做这组对照。
