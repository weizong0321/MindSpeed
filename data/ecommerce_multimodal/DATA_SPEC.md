# 电商导购多模态数据集标注规范（v2）

> 适用：`examples/qwen3_5/qwen3_5_0.8B_config.yaml` 所用的 SFT 数据。
> 目标：让每张图片与答案**严格对应**，模型必须"看图"才能答对。

---

## 0. 一句话说明

图片的"标记"没有独立环节 —— 不需要画框、不需要掩码、不需要单独写 caption。
**图片的标记 = 它放在哪个目录 + `answers.json` 里对应款的那段回答。**

---

## 1. 目录结构

```
data/ecommerce_multimodal/
├── images/
│   └── <category>/            ← 类别（与 questions.json 的键一致）
│       └── <sku>/             ← 款（同一款 = 参数与外观一致的商品）
│           ├── 001.jpg
│           └── 002.jpg
├── questions.json             ← 问法库：按【类别】写
├── answers.json               ← 答案库：按【款】写
├── generate_dataset.py        ← 生成 train.json / eval.json（带质检）
└── generate_dataset_v1_legacy.py  ← 旧版脚本（随机配对），仅作历史答案文本参考
```

类别键（现有 12 个）：
`smart_watch` 智能手表 · `earbuds` 蓝牙耳机 · `power_bank` 充电宝 · `keyboard` 机械键盘 ·
`backpack` 户外背包 · `action_camera` 运动相机 · `desk_fan` 桌面风扇 · `sunglasses` 太阳镜 ·
`gaming_mouse` 游戏鼠标 · `portable_monitor` 便携显示器 · `water_bottle` 运动水杯 ·
`running_shoes` 户外跑鞋

命名要求：类别与款目录名只用**小写字母、数字、下划线**（避免中文/空格/括号）。

## 2. 图片要求

### 2.1 技术约束（由配置决定，不可商量）

配置来源：`examples/qwen3_5/qwen3_5_0.8B_config.yaml` 中
`image_max_pixels: 262144`、`image_min_pixels: 1024`，配合 Qwen-VL 预处理
`patch_size=14 × merge_size=2 = 28`。

| 项 | 要求 | 原因 |
|---|---|---|
| 格式 | jpg / jpeg / png，建议统一 jpg | 脚本已支持 |
| 色彩 | RGB，预先去掉 alpha | 避免通道问题 |
| **面积** | **≤ 262144 像素（= 512×512）** | 超过会被**等比压缩**，多传的部分完全无效 |
| 短边 | **≥ 336**，建议 448–512 | 低于 336 会被**放大**，细节丢失、等于看马赛克 |
| 长宽比 | ≤ 2:1 | 极端长条会把短边压得太小 |
| 视觉 token | 每 28×28 像素 = 1 token；512×512 → 324 token | 决定训练耗时与显存 |

**结论：把图片准备成短边 448–512、总面积 10 万–26 万像素，就够了，再大是浪费。**

### 2.2 内容要求（人眼判断，决定数据质量）

每张图必须满足：

- ✅ **一图一款**：主体占画面 ≥ 1/3，居中，无遮挡
- ✅ 能明确指代"这款"（不能出现两个同类商品）
- ✅ 图里能看见该款 `visible` 里列出的特征

出现以下任一情况，**直接淘汰**：

- ❌ 多商品同框 / 详情页拼图 / 多角度拼在一起
- ❌ 水印、店铺 logo、促销文案、价格标签（模型会去读那些字）
- ❌ 主体过小、严重遮挡、裁剪残缺
- ❌ 模糊、严重压缩失真

### 2.3 可见 / 不可见 对照表（决定一句话能不能写死）

| 能写死 ✅ | 只能写"以商品页标注为准" ❌ |
|---|---|
| 品类、颜色、造型、形状 | 电池容量 mAh、续航小时数 |
| 接口数量与类型（Type-C / 几个口） | 降噪深度 dB、蓝牙版本、防水等级 |
| 有无屏幕 / 按键 / 旋钮 | 材质型号（PBT / ABS）、芯片型号 |
| 佩戴形态（半入耳 / 头戴 / 入耳） | 售价、质保年限、重量克数 |
| 图里可辨的 logo、配件、线材 | 充电功率（W）、传感器精度 |

> v1 的致命问题就在这里：答案里写死 `65W`、`20000mAh`、`579元`，而图里一个都看不到 ——
> 模型学到的唯一策略是"忽略图片、背模板"。

## 3. 标注四步法

```
① 看图 → 属于哪个类别？           → 放进 images/<category>/
② 见过这个款吗？（比颜色+造型）    → 见过 → 放进那个款目录，【结束，不用写字】
③ 是新款                         → 建目录
                                  → 填 visible（4–6 个图上可见特征）
                                  → 写 answer（按第 5 节规范）
④ 复核                           → python generate_dataset.py --check
```

**要点：标注单位是"款"，不是"图"。** 同款的多张图共用同一段答案（参数一致），
所以 2000 张图通常只需写 40–60 段文字，90% 的图片在第 ② 步就结束了。

### 工作量估算（2000 张图）

| 环节 | 耗时 |
|---|---|
| 图片清洗 + 去重（脚本） | 20 分钟 |
| 淘汰不合格图（人眼快速过） | 1–2 小时 |
| 归类到类别目录 | 3–5 小时 |
| 分款 + 写 40–60 段回答 | 5–10 小时 |
| **合计** | **约 1.5–2 个工作日** |

## 3.1 工具化操作（推荐）

本目录提供两个配套工具，把上面四步变成"按键 + 一条命令"：

| 文件 | 作用 |
|---|---|
| `classify_tool.html` | 浏览器归类工具，双击打开即用，**纯本地、不联网、不上传** |
| `apply_labels.py` | 把导出的 `labels.csv` 落地成 `images/<category>/<sku>/` 目录 |
| `tool_test.js` | 归类工具的无头回归测试（`node tool_test.js`） |

### 操作流程

```
① 双击 classify_tool.html（Chrome / Edge）
② 点「选择图片文件夹」→ 选中 data/ecommerce_multimodal/images
③ 逐张标注：按数字键选【类别】→ 按数字键选【款】
      · 某个类别第一次出现的款 → 按 N 输入款名（回车确认）
      · 不确定的图 → 按 S
④ 全部标完 → 点「导出 CSV」得到 labels.csv
⑤ 落地到目录：
      python apply_labels.py --csv labels.csv --src ./images              # 先空跑看计划
      python apply_labels.py --csv labels.csv --src ./images --apply      # 确认后执行（复制）
      python generate_dataset.py --check                                 # 复核
```

### 快捷键

| 键 | 作用 |
|---|---|
| `1`–`9` `0` `-` `=` | ①选类别 / ②选款（按钮上标了对应按键） |
| `N` | 新建款（输入名称，回车确认，Esc 取消） |
| `Esc` | 取消当前类别选择 |
| `S` | 标记"不确定"并跳到下一张（**不会**导出到 CSV） |
| `Z` | 切换"适应窗口 / 原始尺寸"（看细节用） |
| `Backspace` / `←` | 撤销上一张（最多回退 500 步） |
| `→` | 跳过本张（不改动已有标注） |

### 注意事项

- **进度自动保存**在浏览器本地（按文件夹签名分槽，最多 8 个文件夹），关掉浏览器再打开会自动续标
- 换机器/清缓存前，用工具栏「进度」按钮**导出 JSON 备份**，必要时可导入恢复
- 款名会被自动规范化成小写 + 下划线（如 `GT-Runner 50M` → `gt-runner_50m`），与脚本的命名要求一致
- 导出 CSV 带 UTF-8 BOM，Excel 直接打开中文不乱码
- `apply_labels.py` **默认是空跑**，只打印计划不动文件；加 `--apply` 才执行；默认**复制**，加 `--move` 才移动
- 落地脚本会用 `questions.json` 校验类别（写错的类别会被拦下），并检测同名文件冲突
- 效率参考：约 800–1500 张/小时（熟练后每张 2–3 秒）

## 4. `questions.json`：按类别写问法

```json
"smart_watch": {
  "name_zh": "智能手表",
  "questions": [
    {
      "id": "hiking",
      "desc": "户外徒步 / 多约束",
      "rounds": 1,
      "user": "<image>\n我夏天经常徒步登山，预算600以内，……这款合适吗有什么短板？"
    }
  ]
}
```

规则：

- `id` 供 `answers.json` 引用，类别内唯一
- `rounds: 1` → `user` 是**字符串**；`rounds: 2` → `user` 是**字符串数组**（按轮次）
- **只有第 1 轮需要 `<image>\n` 前缀**，后续轮次是追问，不重复贴图
- 问句结构建议五段式：`<image>\n` + ①场景/身份 + ②预算 + ③硬性要求（逐条）+ ④排除项 + ⑤收尾问句

**新增类别 = 在 `questions.json` 加一个键 + 建 `images/<category>/` + 在 `answers.json` 补该类的款。** 三处齐了脚本才认。

## 5. `answers.json`：按款写答案

```json
"smart_watch/gt-runner-50m": {
  "visible": ["黑色硅胶表带", "圆形表盘，外圈有刻度环", "右侧上下两个实体按键", "背面可见 5ATM 防水标识"],
  "caveat": "续航小时数、心率血氧精度、售价均为商品页标注，图中不可见",
  "split": "train",
  "qa": {
    "hiking": "这款完全适配户外徒步场景。图中为黑色硅胶表带配圆形表盘……"
  }
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `visible` | 建议 | 图里**能核对**的特征清单。写 `answer` 时只准引用这里面的东西 |
| `caveat` | 有不可见参数时**必填** | 声明"哪些是图上看不到的"，让模型学会承认看不到 |
| `split` | 必填 | `train` / `eval`，**按款整款划分** |
| `qa` | 必填 | 问法 `id` → 回答；单轮给字符串，多轮给数组（长度必须等于问法轮数） |

### `answer` 写作规范（4 段式）

```
① 结论        "这款完全适配户外徒步场景。"
② 可见特征断言 "图中为黑色硅胶表带配圆形表盘，右侧上下双实体按键，背面可见 5ATM 防水标识"
③ 逐条对照    用户问句里的每个约束都要有一条应答；不可见的补"以商品页标注为准"
④ 主动说短板  仅当用户问了短板/对比时才写
```

三条硬规则：

1. `answer` 里的**每个具体参数**都必须在 `visible` 里，或已被 `caveat` 声明为"以商品页为准"
2. 用户问句里的**每个约束**都要有应答，且顺序一致（这是"逐条核对"行为的训练目标）
3. 多轮问法的第 2 段回答必须**承接语境**（追问句没有主语，靠上一轮理解）

### 免费提升信息密度

同一张图会按 `qa` 的条目数产出多条样本 —— **给同一个款写 2 个不同问法的回答**，
模型就要在同一张图上按不同问题给出不同答案，这是强迫它"看图"的最有效手段，且零额外图片成本。

## 6. 训练 / 验证划分

- `split` 是**款级**字段：同一款的所有图片只能进同一集，**绝不跨集**（否则验证集泄题）
- 验证集建议 **100–200 条**，每类至少留 1–2 个款
- `eval.json` **目前不会进训练**：训练配置只读 `train.json`；它用于离线评测
  （若要训练内验证，需要另配 `dataset` 多文件或 validation 参数）

## 7. 数量建议

| 阶段 | 每类图片 | 类别数 | 总量 | 效果 |
|---|---|---|---|---|
| 只验证流程 | 3–5 | 5 | ~20 | 能跑通 |
| 最低可用 | 10 | 10 | ~100 | 学会"看图 + 按格式答" |
| **推荐起点** | **20–50** | **20–40** | **800–2000** | 真正建立图文对应 |
| 收益递减 | > 80 | — | > 5000 | 单答案样本再多收益变小 |

- 每类 ≥ 20 张是底线；**类内要有视觉差异**（不同颜色/款式/角度），否则模型学到的是"类别 → 模板"
- 同一张图在训练集里重复 ≤ 2–3 次
- 与其堆图片数量，不如**给同款多写一个问法**

## 8. 质检

```bash
cd data/ecommerce_multimodal
python generate_dataset.py --check        # 只检查，不写文件
python generate_dataset.py                # 生成 train.json / eval.json
python generate_dataset.py --root <dir>   # 指定数据根目录
python generate_dataset.py --no-size-check
```

自动检查项：

| 级别 | 检查 |
|---|---|
| 错误 | 图片类别在 `questions.json` 里没有定义 |
| 错误 | 图片的款在 `answers.json` 里没有定义 |
| 错误 | `qa` 引用了不存在的问法 id |
| 错误 | 问法轮数与回答段数不一致 |
| 错误 | `split` 取值非法 |
| 错误 | 答案里出现图中无法核对的数字，但该款没有 `caveat` |
| 错误 | `images/` 根目录不存在 |
| 警告 | 答案里的数字不在 `visible` 中（需人工确认，已由 `caveat` 覆盖） |
| 警告 | 每类图片数 < 20 / 每款图片数 < 2 |
| 警告 | 短边 < 336（会被放大）、面积 > 262144（会被压缩） |
| 警告 | 图片未放进款目录（平铺在类别目录下，已被忽略） |
| 警告 | `answers.json` 里的款没有对应图片目录 |
| 提示 | 哪些类别暂无图片（允许分批备数据） |

只要出现任何**错误**，脚本就不写文件；覆盖已有 `train.json` 前会自动备份为 `train.json.bak`。

## 9. 与训练配置的关系

数据准备好后，`examples/qwen3_5/qwen3_5_0.8B_config.yaml` **不需要改动**：

```yaml
dataset_dir: ./data/ecommerce_multimodal            # images/ 的上一级
dataset: ./data/ecommerce_multimodal/train.json     # 生成出来的训练集
attr: {formatting: sharegpt, images: image, messages: conversations,
       role_tag: from, content_tag: value, user_tag: user, assistant_tag: assistant}
```

注意：数据集内容一变，`cache_dir` 的预处理缓存会失效并**重新预处理（约 12 分钟 / 2000 条）**，属正常现象。

## 10. 常见疑问

**Q：能只分目录、不写 `answers.json` 吗？**
不行。`answers.json` 是答案的唯一来源。只想快速起步，可以每类只写 3–5 个款，把现有图按款归进去。

**Q：同一张图可以出现在两个款里吗？**
不行，一款一目录。图若同时符合两款，选一个更准的。

**Q：`visible` 和 `answer` 里的描述不一致会怎样？**
脚本会报警告/错误（数字核对）。这正是防止"编参数"的闸门。

**Q：v1 的答案文本还能用吗？**
能，作为写作参考：`generate_dataset_v1_legacy.py` 里有 12 类的历史答案，按"按款"格式改写成
`answers.json` 条目即可，不要直接复用（它们含大量图上不可见的参数）。
