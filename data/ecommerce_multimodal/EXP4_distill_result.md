# 实验四（方案 1）：大模型蒸馏 —— 决定性成功

**结论：逐图答案（蒸馏）把"颜色说对率"从 0.69 提到 0.97、"部件说对率"从 0.16 提到 0.50。
模型从"基本不看图"变成了"明显在看图"。这是四轮实验里第一个质变。**

---

## 1. 一句话做法

用 `Qwen3.5-4B` 给每张图标注**结构化可见属性**（品类/主色/可见部件/画面类型），
然后把它替换进子代理已写好的答案里那段「图中为…」从句 —— 其余（结论、逐条对照、
以商品页标注为准、短板）保持不变。

- 不指望大模型写整段答案 → **格式合规由模板保证**
- 描述部分**逐图不同** → 「一个子样式背一段答案」这条路被堵死
- 属性是结构化的 → **可客观校验**，于是有了能算的指标

## 2. 结果（同一验证集 sample6/eval.json，各 98 条）

| 模型 | **颜色命中率** | **部件命中率** |
|---|---|---|
| BASE（原始权重） | 0.469 | 0.158 |
| sample5（一组共用一段答案） | 0.694 | 0.156 |
| **sample6（逐图答案 · 蒸馏）** | **0.969** | **0.499** |

指标含义：
- **颜色命中率** = 生成答案里出现了该图**真实主色**的比例
- **部件命中率** = 该图真实可见部件中，被答案提到的比例

**两个关键读法：**
1. **颜色 0.469 → 0.969**：从"差不多一半能说对"到"基本都能说对"
2. **部件上 sample5（0.156）≈ BASE（0.158）—— 一组一段答案对部件毫无帮助**；
   只有逐图答案才把它拉到 0.499（3.2 倍）

## 3. 这回答了之前所有实验没能回答的问题

| 假设 | 实验 | 结论 |
|---|---|---|
| 子样式纯度不足 | sample3 → sample4 | ✅ 成立（B−A +0.025 → +0.223） |
| 答案设计 / 模型容量 / 分辨率 | 逐项排除 | ❌ 都不是主因 |
| 子样式数量不足 | sample4 → sample5 | ❌ 不成立（+0.223 → +0.078） |
| **"一组共用一段答案"这个结构** | **sample5 → sample6** | ✅✅ **就是它** |

四轮下来，最后一个变量被证实是根因，而且改掉它之后指标出现质变。

## 4. 顺带解决的：自动纯度检测

之前三种嵌入指标（簇心纯度 / 二分轮廓 / 严格阈值连通分量）全部无法区分"同款"与
"看起来像"。**标注分歧却可以**：

- 同一子样式内 VLM 判出的品类若不一致 → 就是混款
- 实测抓到的例子：`bag_backpack_002` 有 60% 的图被判成**单肩包**（它被错标进了背包类）；
  `shoes_leather_008` 100% 被判成**运动鞋**（它本是童鞋）
- 本次 57 个子样式里自动丢弃 6 个（品类一致率 < 0.7），保留 51 个

这比人眼 30 秒/表的核验更省（全自动），但注意它**抓不到"同类不同款"**
（`bag_handbag_007` 一致率 1.00，实际混了三种包型）——两者互补。

## 5. 蒸馏流水线（可复制到 85k 张）

```
1) caption_images.py     Qwen3.5-4B 逐图标注 → JSONL
                        855 张 / 1.7 s/张 / 0 解析失败 / 24 分钟
2) compose_from_attrs.py 品类一致性筛纯度 + 逐图答案合成
                        → 49 子样式 / 735 图 / 1176 训练 + 294 验证
3) 训练                  0.8B / 2 epoch / 2352 iter / 约 30 分钟
4) eval_attrs.py         颜色命中率 + 部件命中率（客观、可自动）
```

外推到 85,575 张：标注约 **40 小时**（1.7 s/张，可分批并行），训练数据约 2,000 子样式
× 15 图 → 训练规模会大到需要重新设计 epoch 数；但**方法与指标已经验证可用**。

## 6. 必须说明的局限（避免过度乐观）

1. **验证集只有 98 条**（per-sku=1）。要更稳的结论应跑 294 条（约 3 倍时间）。
2. **"真值"来自 4B 教师**，而我人工抽检 8 张发现教师颜色约 75% 准、品类约 87% 准。
   学生的高命中率部分是在"复现老师的说法"，**上限受教师质量限制**。
   要进一步提升，应换更强的教师（`Qwen3-VL-30B-A3B-Instruct` 就在服务器上，54GB）。
3. **"同子样式不同图重合度 = 0.000" 是伪值**：per-sku=1 时每个子样式只有 1 张图，
   没有可比对的对子。这个指标本轮无效。
4. **仍未验证跨品类泛化**：49 个子样式 / 19 品类是小规模；
   真实场景是任意商品图，需要更大规模 + 留出未见品类。
5. 部件命中 0.499 说明**细节描述仍不完整**——一半的可见部件没说。

## 7. 对"是否可用"的回答

| 能力 | 现在 | 说明 |
|---|---|---|
| 输出格式与话术 | ✅ 可用 | 四段式稳定 |
| 不编造参数 | ✅ 可用 | 全程以商品页标注为准 |
| **说对商品主色** | ✅ **接近可用（0.97）** | 蒸馏后 |
| 说全可见部件 | ⚠️ 部分可用（0.50） | 一半的部件能说对 |
| 跨品类泛化 | ❓ 未验证 | 需要更大规模实验 |

**定位：作为一个"能看准主色、说对部分结构、不编参数"的导购回答基座，已经接近可用；
但还没到能直接对客的程度**，主要差在细节完整度与规模验证。

## 8. 复现命令

```bash
# 1) 逐图标注（约 24 分钟 / 855 张）
python examples/qwen3_5/caption_images.py \
  --model /workspace/shared_assets/models/Qwen/Qwen3.5-4B \
  --root data/ecommerce_multimodal/sample5/images \
  --out /workspace/user_data/captions_all.jsonl --batch-size 8

# 2) 筛纯度 + 合成逐图答案
python examples/qwen3_5/compose_from_attrs.py \
  --captions /workspace/user_data/captions_all.jsonl \
  --data sample5 --out sample6 --min-agree 0.7

# 3) 训练
CONFIG=examples/qwen3_5/qwen3_5_0.8B_sample6_config.yaml bash examples/qwen3_5/train_qwen35.sh

# 4) 转 HF + 评测
mm-convert Qwen35Converter dcp_to_hf \
  --dcp_dir /workspace/user_data/output/qwen3_5_0.8B_sample6/iter_0002352 \
  --save_hf_dir /workspace/user_data/output/qwen3_5_0.8B_sample6_hf \
  --origin_hf_dir /workspace/user_data/output/qwen3_5_0.8B_hf
python examples/qwen3_5/eval_attrs.py --model <HF目录> \
  --data sample6 --images sample5 --per-sku 1 --tag s6 --out eval_s6.json
```

## 9. 本轮新踩的坑

1. **glusterfs 上写小文件会挂**：预处理缓存写在 `/workspace/user_data`（glusterfs）
   触发 `OSError: [Errno 107] Transport endpoint is not connected`，且**缓存目录删不掉**
   （残留卡死句柄）。→ 缓存改放本地 overlay `/workspace/cache_sample6`。
2. **`dataset_dir` 与 `dataset` 可以不同目录**：sample6 的标签在 sample6、图片在 sample5，
   评测脚本要加 `--images` 参数分别指定。
3. **教师模型必须关 thinking**：Qwen3.5-4B 默认会先输出一大段分析，JSON 挤不出来；
   `apply_chat_template(..., enable_thinking=False)` 后解析率从 0/3 变成 855/855。
4. **批处理是关键**：单张 21–31 s/张 → bs=8 后 1.7 s/张（提速 15 倍）。
